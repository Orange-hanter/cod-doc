# Zsh-дополнение для `cod-doc`

Дополняет команды, опции **и живые значения из БД**: слаги проектов, `task_id`
с заголовком и статусом, `doc_key`, `plan.scope`, буквы секций, якоря секций
документа, `adr_id`, `story_id`, `scenario_id`, имена рутин и адаптеров.

```
$ cod-doc task show -p <TAB>
cod-doc      -- /Users/dakh/Git/_my/cod-doc
orakul       -- /Users/dakh/Git/_my/Mozarella/Orakul
zairgrush    -- /Users/dakh/Git/_my/ZAIrgRush
...

$ cod-doc task show -p cod-doc <TAB>
ADO-001  -- done · Починить ~/.cod-doc/config.yaml …
ADO-002  -- done · Корневой README.md — что это, кому, quick start …
...
```

## Установка

```bash
scripts/install-zsh-completion.sh     # симлинк в $fpath + сброс zcompdump
exec zsh
```

Скрипт кладёт симлинк в `~/.oh-my-zsh/custom/completions/_cod-doc` (oh-my-zsh
держит этот каталог в `$fpath` безусловно; править `.zshrc` не нужно). Без omz
— в `~/.zsh/completions`, и тогда каталог надо добавить в `fpath` руками:

```zsh
fpath=(~/.zsh/completions $fpath)   # ДО вызова compinit
```

Вручную, одной строкой:

```zsh
mkdir -p ~/.oh-my-zsh/custom/completions && \
ln -sfn "$PWD/cod_doc/cli/completion/_cod-doc" ~/.oh-my-zsh/custom/completions/_cod-doc && \
rm -rf ~/.zcompdump* && exec zsh
```

Симлинк, а не копия: `cod-doc`, поставленный editable-режимом, смотрит в этот
же чекаут, поэтому симлинк держит дополнение в ногу с CLI после обычного
`git pull`.

Если репозитория на диске нет (`pip install cod-doc`):

```bash
cod-doc completion zsh > ~/.zsh/completions/_cod-doc
```

Команда печатает **закоммиченный артефакт дословно**, ничего не генерируя —
одно чтение файла, байт-в-байт то, что проверил CI.

## Почему дополнение не зовёт `cod-doc`

| источник значений | время |
|---|---|
| `cod-doc --help` | 470 мс |
| `cod-doc task list -p X --json` | 710 мс |
| `cod-doc project list` | 870 мс |
| `sqlite3 -readonly … "select …"` | 10–21 мс |
| `awk` по `~/.cod-doc/config.yaml` | < 10 мс |

`cod_doc/cli/__init__.py` импортирует все 26 групп жадно, а `cmd_hub` тянет
alembic (133 мс) и SQLAlchemy (69 мс). Полсекунды на нажатие TAB — это не
дополнение, поэтому `prelude.zsh` читает реестр `awk`'ом, а всё остальное —
одним `sqlite3 -readonly`. БД в режиме WAL, параллельное чтение безопасно.

Кэша нет намеренно: 20 мс ниже порога восприятия, а протухший кэш («создал
ADO-500, жму TAB — её нет») дороже любой экономии.

## Как понимается «какой проект»

`_cod_doc_slug` пробует три источника по порядку:

1. уже разобранный `-p` / `--project` — `_arguments` кладёт `opt_args` в
   динамическую область видимости, и action-функции он виден даром;
2. ручной скан `$words` — когда дополняем позиционный **до** `-p`, и для
   слитной формы `-pcod-doc`;
3. подъём от `$PWD` к ближайшему `.cod-doc/state.db`.

Запись реестра с непустым `db_url` разбирается **по схеме**, а не по
«null / не-null»: `sqlite:////…` — обычный читаемый файл, а hub на Postgres
пропускается (дополнять нечем). Это повторяет `db_url_for_entry` из
`cod_doc/infra/db.py`.

Любая осечка — тихий `return 1` и ноль вывода: нет `sqlite3`, нет файла, БД
занята, схема не та, пустой результат. Тогда zsh просто уходит в `_default`,
а не сыплет ошибками поверх промпта.

## Устройство

```
cod_doc/cli/completion/
  zsh.py        рендерер: click-дерево -> текст _cod-doc
  sources.py    таблицы «дест параметра -> источник» + весь SQL
  prelude.zsh   рукописный runtime, вшивается в артефакт дословно
  _cod-doc      СГЕНЕРИРОВАННЫЙ артефакт (в git, package-data)
  cmd.py        `cod-doc completion zsh`
  __main__.py   python -m cod_doc.cli.completion --write|--check
```

Регенерация после любой правки CLI, `sources.py` или `prelude.zsh`:

```bash
python -m cod_doc.cli.completion --write
git add cod_doc/cli/completion/_cod-doc
```

Забыл — упадёт `tests/cli/test_zsh_completion_drift.py` с готовой командой в
сообщении. Проверить без записи: `python -m cod_doc.cli.completion --check`.

Форма вывода — идиома `_git`: `_arguments -C` с диспетчером по `->state` и
отдельной функцией на каждую команду (`_cod_doc_task_show` можно позвать
руками для отладки). Дополнение статусов, типов и приоритетов берётся из
`click.Choice` даром — значит, оно всегда совпадает с тем, что CLI реально
примет.

## Живая проверка

```bash
.venv/bin/python scripts/check-zsh-completion-live.py
```

Поднимает интерактивный zsh в pty со СВОИМ `ZDOTDIR` и `fpath` (окружение
пользователя не трогается), нажимает настоящий TAB и смотрит, что вернулось.
Девять кейсов: пять обязаны дать кандидатов (команды, подкоманды, слаги,
task_id, plan.scope), четыре — промолчать (нет реестра, несуществующий слаг,
проект на Postgres, нет `sqlite3` в PATH).

В CI не входит: нужен pty, а на runner'е это лишняя флакующая зависимость.
Но прогонять после правок `prelude.zsh` или формы спек обязательно — рекурсию
на автозагрузке (см. ниже) не видит ни `zsh -n`, ни юнит-тесты. Только TAB.

## Грабли, на которые уже наступили

- **`local path` в zsh ломает `$PATH`.** Переменная специальная и привязана к
  массиву `path`; локальное объявление тихо ломает и поиск команд, и сам
  цикл. Отсюда суффикс `entry_*` в `prelude.zsh`. Стережёт
  `test_prelude_avoids_zsh_special_parameter_names` — там же `status`,
  `reply`, `commands`, `functions`, `options`, `fpath`.
- **Guard на КОРНЕВОЙ функции даёт бесконечную рекурсию.** Тело файла
  `#compdef` *становится* телом функции-заглушки, поэтому
  `(( $+functions[_cod-doc] ))` к моменту исполнения уже истинно: определение
  пропускается, а завершающий `_cod-doc "$@"` зовёт заглушку снова — и так до
  «maximum nested function level reached». `_git` по той же причине
  переопределяет себя безусловно (его строка 8380), а guard'ит только
  хелперы. Ни `zsh -n`, ни юнит-тесты такой файл не отличают от рабочего —
  ловится только `scripts/check-zsh-completion-live.py`.
- **`file:`-URI требует percent-encoding**, а пути проектов содержат пробелы.
  Поэтому `sqlite3 -readonly <плоский путь>`, а не `file:…?mode=ro`.
- **WAL-базу без `-shm` рядом нельзя открыть только на чтение.** SQLite
  обязана создать разделяемый индекс, а `-readonly` ей это запрещает —
  `SQLITE_CANTOPEN(14)`. Состояние штатное: `-wal` и `-shm` удаляются при
  чистом закрытии последнего соединения, то есть у спокойного проекта их
  обычно и нет. Без фолбэка дополнение молча пустело бы именно там, где всё
  в порядке. Поэтому второй заход — обычное открытие с `pragma query_only=1`:
  данные изменить нельзя, служебный `-shm` создать можно. Побочный эффект —
  появление `-wal`/`-shm` рядом с БД, ровно как от любого вызова `cod-doc`.
  Соблазн решить это через `?immutable=1` — ловушка: он обходит WAL и отдаёт
  устаревшие строки, что хуже пустого списка.
- **Имена колонок зашиты строками**: `user_story.narrative` (не `title`),
  `routine.enabled` (не `status`), `plan.scope` в роли идентификатора.
  Миграция, переименовавшая колонку, сломала бы дополнение молча — ловит
  `tests/cli/test_zsh_completion_queries.py`, гоняющий каждый запрос по свежей
  схеме (`alembic upgrade head`).
- **`compinit` сверяет счётчик файлов, а не список.** Строка `#files: N` в
  дампе против числа `_*` в `$fpath`: добавление файла обычно вызывает
  пересборку, но одновременные добавление и удаление гасят друг друга, и новое
  дополнение молча игнорируется. Поэтому установщик сносит `~/.zcompdump*`.
- **`compinit -i` молча выбрасывает «небезопасные» каталоги** (group/world
  writable). Установщик прогоняет `compaudit` и предупреждает.
- **`:` в заголовке ломает `_describe`** — он режет по первому двоеточию.
  Вычищаем в SQL (`replace(title, ':', ' -')`): там дешевле и точнее.

## Чего дополнение намеренно не делает

Не подсказывает значения там, где вводится **новый** идентификатор
(`task create --id`, `doc create --key`, `adr new --adr-id`,
`story create --id`, `scenario new --id`, `adapter add NAME`): список занятых
id там только мешает. Таблица — `NO_COMPLETE` в `sources.py`.

Не дополняет свободный текст: `--title`, `--description`, `--reason`,
`--author`, `--head-sha`, поисковый запрос и полиморфные `--ref` / `--to-ref`.

Известное ограничение: у команд с двумя позиционными одного вида —
`task remove-dep TASK_ID BLOCKER_ID` и `adr supersede` — второй аргумент
получает тот же список, что и первый, включая уже набранное значение. Сузить
его (для `remove-dep` — до реальных рёбер `dependency`) можно, но это требует
позиционно-зависимого источника; сейчас не сделано осознанно.
