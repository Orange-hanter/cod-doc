# Audit — Plan `adr-registry-2026-10`, Section B closure («Полки»)

> **Контекст.** [RFC 34](../../../proposals/34-adr-registry.md) §3.4: у ADR
> одна полка — тема, о чём решение, — или ни одной («Без темы»). Человек
> заводит полки и задаёт им порядок, список ADR группируется по полкам.
> Связи и сигналы — секция A ([отчёт](./2026-10-06-adr-registry-section-a.md)),
> выбор полки агентом — секция C.

## 1. TL;DR

Секция B закрыта: 4/4 задачи `done`, код в `main` (#181, #182, #186). Полки
живут в своей таблице `adr_topic` (миграция 0046), у ADR — `topic_id`;
управление полками — CLI `adr topic …`, MCP `adr_topic_*`, веб-страница
«Shelves»; список ADR сгруппирован по полкам. Реестр cod-doc разложен: 14 ADR
на 6 полках, «Без темы» пуста.

Статус `resolved` — по коду в `main`, а не по действующему рантайму: сервисы
на момент отчёта собраны на `5725ab6` (#182), правки ревью из #186 и полировка
из #188 доедут после `cod-doc update`. Проверки браузером шли на сервере из
ветки с этими правками поверх копии живой БД.
