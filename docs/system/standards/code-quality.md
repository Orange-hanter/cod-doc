# Code Quality Standard

> Политика качества кода: что означают KISS/DRY/SOLID в этом репозитории,
> какой инструмент какое правило стережёт, и как устроен ratchet
> существующего долга. Единственный источник истины для конфигурации —
> `pyproject.toml`; этот документ объясняет **почему** она такая.

## 1. Принципы → инструменты

| Принцип | Чем обеспечен | Где |
|---|---|---|
| **Обязательные типы** | mypy `strict` на весь `cod_doc/` + ruff `ANN` (линт-уровень: недостающие аннотации видны до запуска mypy) | `[tool.mypy]`, `select += ANN` |
| **Запрет `Any`** | ruff `ANN401` — голый `param: Any` / `-> Any` запрещён; `**kwargs: Any` разрешён осознанно (`allow-star-arg-any`); mypy `disallow_any_unimported` — `Any` не протекает из нетипизированных зависимостей | `[tool.ruff.lint.flake8-annotations]` |
| **Запрет магических чисел** | ruff `PLR2004` — сравнение с числовым литералом требует именованной константы. Только код: в тестах литералы — это тестовые данные | `select += PLR2004` |
| **KISS (сложность)** | ruff `C901`: цель — 10, жёсткий потолок — **15**. Порог не поднимается никогда; существующие нарушители — в ratchet (§3) | `[tool.ruff.lint.mccabe]` |
| **Мёртвый код — дефект** | mypy `warn_unreachable`. Ложные срабатывания (mypy сужает member-выражения через вызовы) и форвард-совместимые guard'ы глушатся **точечным** `# type: ignore[unreachable]` с комментарием-обоснованием — см. `agent/orchestrator.py:606`, `link_service/resolver.py:484` | `[tool.mypy]` |
| **Дисциплина return / перф-мелочи / pathlib** | ruff `RET`, `PERF`, `PTH` | `select` |
| **DRY** | Не линтуется — ловится на ревью. Правило большого пальца: третья копия шейпа = вынос в общий модуль. Известный долг: `_make_session`/`_require_project_id` продублированы в 8 CLI-модулях (`cli/*/`_common.py`) — кандидат на консолидацию |
| **SOLID (границы слоёв)** | Однонаправленность `cli/tui/api/mcp → services → domain ← infra` — контракт [ARCHITECTURE.md](../ARCHITECTURE.md); «новая функциональность = все четыре поверхности» — AGENTS.md §5. Автоматической проверки направлений импортов пока нет (кандидат: import-linter, отдельным решением) |

## 2. Что решили НЕ включать (и почему)

| Правило | Причина отказа |
|---|---|
| mypy `disallow_any_explicit` | 502 ошибки: `dict[str, Any]` — легитимная форма MCP/JSON-payload'ов. Пересмотр — только вместе с типизацией payload'ов через TypedDict |
| `PLR0913` (много аргументов) | 97 нарушений: keyword-only сигнатуры сервисов (`task_service.create` и т.п.) — осознанный house style, а порог, пропускающий текущий код, бессмыслен |
| `ARG` (неиспользуемые аргументы) | Шум на интерфейсных реализациях (click-callbacks, event-listeners, протоколы) |
| `A002` (тень builtin'ов в параметрах) | `type=`, `id=`, `hash=` — публичные имена параметров MCP/CLI, зеркалящие поля домена; переименование = слом контракта |

## 3. Ratchet: как гасится существующий долг

На момент включения политики (2026-08-25) в `pyproject.toml
[tool.ruff.lint.per-file-ignores]` зафиксирован список файлов-нарушителей:
**ANN401 — 40 мест · PLR2004 — 39 · C901 — 14 функций · PERF401 — 25**
(это те, чей авто-фикс ruff счёл небезопасным).

Правила ratchet'а:

1. **Список только уменьшается.** Починил файл — удали его строку из
   per-file-ignores в том же PR.
2. **Новые файлы в список не добавляются.** Новая запись в ratchet-блоке —
   это отклонение политики и предмет ревью, а не способ починить CI.
3. Точечный `# noqa: <RULE>` / `# type: ignore[<code>]` в новом коде
   допустим только с комментарием-обоснованием на той же строке или строкой
   выше.
4. Снятие правила целиком — только правкой этого стандарта с записью в §2.

## 4. Gate

Ровно тот же, что в CI (`.github/workflows/ci.yml`), без изменений:

```bash
.venv/bin/ruff check cod_doc/ tests/
.venv/bin/ruff format --check cod_doc/ tests/
.venv/bin/mypy cod_doc/
.venv/bin/pytest tests/ --tb=short
```

⚠️ Прогоняя тесты из окрашенной терминальной сессии, снимайте `FORCE_COLOR`
(`env -u FORCE_COLOR`): rich красит вывод CLI внутри `CliRunner`, и строковые
ассерты падают на ANSI-кодах.
