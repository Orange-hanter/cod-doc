# Release: sprint M4 "Proof of Value" (2026-08-30)

# Sprint M4 "Proof of Value" — release note (2026-08-30)

Sprint M4 closed the main question of Phase 3: **does cod-doc give measurable value to live projects**, not just pass tests. The answer was obtained on three fronts: an alien documentation corpus, the live ZAIrgRush loop, and the full ingest AI-review contour.

## What was included

### 1. Orakul: 405 documents under management (ADO-062, ADO-064)

- The Orakul project was re-registered on the current schema (migrations 0027/0028 on an existing DB, data preserved).
- M3 fidelity fixes verified on a live corpus: **405/405 documents, 0 stale_export, 0 missing**.
- Incident: a mass `--force-write` rewrote the author's frontmatter (invalid YAML fell into a "discrepancy"). Damage rolled back in minutes; the root was closed by fix **ADO-064**: unparseable frontmatter = "cannot prove a discrepancy" → verbatim. Lesson recorded: guards of destructive flags are read to the end, dry-run is mandatory on mass operations.

### 2. E5-C: doc-context proven in battle on OpenRouter (ADO-063)

The first run of the ZAIrgRush loop, fully paid via OpenRouter (clean accounting, a $5 key with a 1-hour TTL):

- executor: kimi CLI → `qwen/qwen3.8-27b` via an isolated `KIMI_CODE_HOME`;
- reviewer: claude CLI → `anthropic/claude-sonnet-5` via the OpenRouter Anthropic-skin.

**Result:** task s5dc (`format_csv_line` per the convention from cod-doc) — **done on the 1st iteration**, review approve, gate of 119 tests green. The document block reached the executor's prompt, the implementation follows the documented convention verbatim — the task's trap did not trigger. **Cost of the run: $0.98.** Verdict per RFC 22 §3.4: **scalable**.

Mechanics: `ctx docs --include-body` (cod-doc) + path priority `task.doc_paths → doc_context_paths → fail-open` (ZAIrgRush).

### 3. Activity events: full write-path (ADO-040)

- A unified helper `emit_for_write` / `write_revision_and_emit_event`: revision + activity event + run_id atomically in one transaction.
- Write-site coverage: adr 6/6, approval 3/3, task_doc 2/2, story 5/5, comment 3/3, checkout 3/3, commit_link 1/1, link resolver 4/4, repo_index 1/1, doc 6/6.
- Swallowing of emit errors in task_service eliminated — an event error is now visible and rolls back the transaction.

### 4. Ingest ai_review: pull-model (SYM-009)

- `cod-doc ingest ai_review --from-pr N [--repo PATH]` — downloads the GitHub Actions artifact `pr-review-export-N` and imports findings with deduplication.
- An idempotent poller `scripts/ingest-orakul-reviews.sh` (state file, dry-run) — ready to be put on cron.
- Verified in battle: 3 historical Orakul PR-exports imported, the repeated finding `no-math-round-ts` has `times_seen=4`, the Orakul working tree untouched.
- Upstream: PR [Orange-hanter/ai-reviewer#5](https://github.com/Orange-hanter/ai-reviewer/pull/5) — `fp/verifierStatus/actionabilityScore` in slimFinding, `EXPORT_VERSION=2` (additively). The cod-doc adapter already understands v2.
