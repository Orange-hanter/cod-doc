# Task Quality Gates — линтер и гейты качества задач

# Task Quality Gates — дизайн

**Статус:** draft | **Дата:** 2026-09-15 | **Источник:** анализ пустых задач NXT-001…028 в проекте zairgrush

## Проблема
Пакетный импорт бэклога (28 задач за 1 секунду из журнальных документов) создал карточки-закладки: без постановки, без ссылок, без связей, со статусной стенограммой вместо описания. Контрольный пример WAV-003 (создана вручную) показал: дефект воспроизводится и без импорта — привязки не делает никто, потому что это отдельная необязательная работа, а `task_create` принимает что угодно.

## Корневые причины
1. Описание копируется из журнала как есть — норма «задача читается с холодного старта» не закреплена механизмом.
2. Description смешивает постановку и статус — статусные механизмы (task_log_progress) существуют, но не навязаны.
3. Привязки (affects_files, task_doc, dependency) — отдельные вызовы, которые никто не делает.
4. Нет валидации на создании и нет качественного сигнала исполнителю.

## Решение: 6 механизмов
- **M1 Task Lint** — детерминированный линтер карточки (Q1–Q5), ядро всех гейтов. Сервис + MCP-инструмент `task_lint`.
- **M2 Creation Gate** — CLI `cod-doc task new`: find_duplicate → create → lint → rollback при нарушениях; draft-режим пакетного импорта; обход только через --force с событием `task.lint_bypassed`.
- **M3 Link Resolver** — `task_link_resolve`: парсит description, разрешает пути в affects_files (расширение `task_update`) и task-id в dependency edges; dry-run по умолчанию.
- **M4 Hygiene Routine** — новый check_name `task_quality` в существующей routine-системе: weekly lint живого бэклога, QLT-задачи на доразбор.
- **M5 Executor Gate** — поле `quality` в `agent_pick`; контракт «quality.ok=false → agent_report needs_context» в skill task-standard.
- **M6 Supersede Flow** — при дедуп-хите: cancel старой задачи с reason «superseded by X» + relates-edge; закрывает сценарий дублей NXT-009/WAV-003.

## Правила линтера (M1)
- Q1: description ≥ 300 символов, секции «Цель» и «Зачем»
- Q2: нет статусного зачина (regex «Всё готово|СДЕЛАН|ОСТАЛОСЬ|ждёт|PREP» в первых 200 символах)
- Q3: ≥1 привязка — affects_files, task_doc или существующий на диске путь в тексте
- Q4: acceptance содержит проверяемый якорь (число, путь, имя метрики/правила)
- Q5: упомянутые task-id существуют в базе

## Границы
- Линтер детерминированный, без LLM — дёшево в гейтах и cron.
- Гейт навязывается только на CLI-обёртку; прямой task_create остаётся для миграций (помечается lint_bypassed при обходе).
- Legacy-задачи не блокируются, а разбираются через M4.
